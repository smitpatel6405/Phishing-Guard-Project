PROJECT: PHISHGUARD - Real-Time Phishing Detection System
===========================================

PROJECT OVERVIEW
----------------
PhishGuard is a real-time phishing detection system that protects users while they browse the web. It consists of two main components:
1. Flask Backend API (Python) - Analyzes URLs using machine learning
2. Chrome Browser Extension (JavaScript) - Captures URLs and displays warnings to users

When a user visits any webpage, the extension automatically sends the URL to the backend API, which analyzes it and returns a prediction (PHISHING or LEGITIMATE) with a confidence score. The extension then displays color-coded warnings (Red/Yellow/Green) to alert the user.

ARCHITECTURE & HOW IT WORKS
----------------------------
1. User visits a webpage → Chrome Extension captures the URL
2. Extension sends URL to Flask backend API (POST request to /predict endpoint)
3. Backend extracts 9 URL features and runs ML model (RandomForest classifier)
4. Backend applies multi-layer security checks:
   - Layer 1: Allowlist/Denylist check (instant verdict for known domains)
   - Layer 2: ML prediction (RandomForest model)
   - Layer 3: Content heuristics (iframe count, external scripts, etc.)
   - Layer 4: Optional reputation API (Google Safe Browsing)
5. Backend returns JSON response with prediction, confidence, and features
6. Extension displays result in popup with color coding and detailed info

BACKEND API ENDPOINTS
---------------------
1. GET / → API information
2. GET /health → Health check endpoint (returns {"status": "healthy"})
3. POST /predict → Main phishing detection endpoint
   - Input: {"url": "https://example.com", "page_signals": {...}, "visual_signals": {...}}
   - Output: {
       "prediction": "PHISHING" or "LEGITIMATE",
       "confidence": 0.85,
       "features": {...},
       "url": "https://example.com"
     }

4. POST /predict_fused → Advanced visual analysis endpoint (uses screenshots)

MACHINE LEARNING MODEL
----------------------
- Algorithm: RandomForest Classifier
- Features: 9 URL-based features
- Model File: models/phishing_model.pkl (pickle format)
- Training: Uses scikit-learn
- Output: Binary classification (phishing/legitimate) with confidence score

FEATURE ENGINEERING (9 Features)
--------------------------------
The system extracts these 9 features from any URL:
1. url_length - Total character count of the URL
2. number_of_dots - Count of dot characters (.)
3. has_https - Boolean (1 if HTTPS, 0 if HTTP)
4. has_ip_address - Boolean (1 if URL contains IP address)
5. has_www - Boolean (1 if URL has www subdomain)
6. has_subdomain - Boolean (1 if URL has additional subdomains)
7. domain_length - Length of the domain name
8. path_length - Length of the URL path
9. has_suspicious_words - Boolean (1 if URL contains suspicious keywords like "secure", "login", etc.)

MULTI-LAYER SECURITY ARCHITECTURE
---------------------------------
Layer 1: Allowlist/Denylist
- Instant verdict for known domains
- ALLOWLISTED_DOMAINS: google.com, paypal.com, microsoft.com, etc.
- DENYLISTED_DOMAINS: Known phishing domains
- Confidence: 99% (instant bypass)

Layer 2: Machine Learning
- RandomForest classifier on 9 URL features
- Confidence threshold: 80% (configurable via PG_PHISHING_THRESHOLD env var)
- Performance: <100ms

Layer 3: Content Heuristics
- Analyzes page content (iframes, external scripts, brand mismatches)
- Checks for suspicious patterns
- Confidence: 85%

Layer 4: Reputation API (Optional)
- Google Safe Browsing API integration
- Requires GSB_API_KEY environment variable
- Confidence: 95%
- Timeout: 4 seconds
